# Project hooks

Reldens enforces its quality bar in layers so the bar holds without slowing the
Claude Code edit loop. These hooks are the local, always-on part. They are checked in, so
they run for every contributor.

## What runs, and when

| Layer | Mechanism | When | Cost | Blocks? |
|---|---|---|---|---|
| Generated-file guard | `PreToolUse` hook -> `deny-generated-edit.sh` | every Edit/Write call | milliseconds | yes, on a generated target |
| Instant copy gate | `Stop` hook -> `qa-stop.sh` | end of every turn | milliseconds | yes, on a hit |
| Deterministic floor | `.githooks/pre-push` | once per `git push` | seconds | yes, on red |
| Full review | the `.claude/agents/` reviewers | when you finish a unit of work | an agent run | no (advisory) |

- **`deny-generated-edit.sh`** blocks a direct Edit/Write to a generated artifact
  (anything under `generated-entities/` and any `*.generated.js` file): those are
  regenerated by `reldens generateEntities --override`, never hand-edited. Regenerators
  are unaffected (they write via the CLI, which a PreToolUse hook on Edit/Write never
  sees). It fails open on anything unexpected so a broken guard cannot wedge the edit
  loop.
- **`qa-stop.sh`** scans the uncommitted added lines in the working tree (the tracked
  diff against HEAD, staged and unstaged, plus untracked text files), for hard invariants
  that are detectable instantly: an em dash, en dash, or emoji; a stray `.only(` that
  would silently disable a test suite; a leftover `debugger`; and a `console.log` call
  added to a server file under `lib/` (server code must use `@reldens/utils` Logger).
  Lockfiles (`*.lock`, `package-lock.json`) are excluded; `node_modules` and dist builds
  are gitignored so they never appear. On a hit it asks Claude to fix those lines before
  finishing; otherwise it is silent. It never runs the tests, the build, or any agent. A
  Stop hook fires every turn, so anything heavier here would tax every iteration, and a
  hook is a shell command that cannot spawn an agent anyway.
- **`pre-push`** runs the heavier deterministic checks once, at the push boundary
  (infrequent, so it does not slow the inner loop): the fast pure unit tests under
  `tests/` (TOTP, auth-throttle, scrypt, chat, moderation, msg rate limit, blockchain)
  plus a copy-rule scan of the working tree mirroring `qa-stop.sh`. It deliberately does
  NOT run the full `npm test`, which needs a live server and DB - that is the documented
  manual step for release candidates. Bypass in a genuine emergency with
  `git push --no-verify`.
- **`ensure-hooks.sh`** (a `SessionStart` hook) points this clone's `core.hooksPath` at
  `.githooks` so the pre-push floor actually runs. It is idempotent and only acts when
  nothing already owns the local hook path, so it never clobbers husky or your own
  repo-local setup (a globally configured `core.hooksPath` is shadowed for this repo, the
  one edge it cannot respect). When an existing value points at another checkout's
  `.githooks` (common with multiple worktrees) it warns without changing anything, since
  the floor that runs would be that other checkout's copy.

The judgment layer (performance, security, migration safety) is not in a hook because a
hook cannot reason. Run the reviewers in `.claude/agents/` (hot-path-reviewer,
security-reviewer, migration-safety) when you finish a feature; they are advisory, not
gating.

## Trust and safety

These scripts run shell on your machine with your permissions, so treat them like any
other checked-in tooling. They are deliberately small and auditable: bash plus `git` and
`perl` (both already required to work on this repo), they read only `git diff`, `git
config`, the untracked files git reports, and the hook's own stdin; they write nothing
outside `.git/config`'s `core.hooksPath`, and make no network calls. Claude Code does
not run project hooks until you have confirmed trust for the repo. Review any change to
these scripts like any other executable, with the same care as a CI script.

## Opting out

- Skip the pre-push floor for one push: `git push --no-verify`.
- Disable the checked-in hooks entirely for your clone: `git config --unset core.hooksPath`.
- Disable the Claude Code hooks: set `"disableAllHooks": true` in your
  `.claude/settings.local.json` (which is not checked in), or remove the `Stop` /
  `PreToolUse` / `SessionStart` entries there.
